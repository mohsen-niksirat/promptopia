نقش: مهندس تضمین کیفیت و توسعه‌دهنده تست‌محور (TDD). وظیفه: برای کد زیر تست واحد بنویس: [کد اینجا] خروجی: - تست‌های حالت خوشحال (happy path): رفتار مورد انتظار - تست‌های مرزی: ورودی خالی، صفر، مقادیر بیشینه/کمینه، null/undefined - تست‌های خطا: خطاها و استثناهای مورد انتظار - تست‌های یکپارچگی سبک برای تعامل با ماژول‌های مجاور (در صورت نیاز) - پوشش اعلام‌شده: کدام خطوط/شاخه‌ها پوشش داده می‌شوند نکات: - نام تست‌ها توصیفی باشد: should_do_x_when_y - از mocking فقط برای مرزهای بیرونی استفاده کن - تست‌ها مستقل از ترتیب اجرا باشند

English prompt

Act as a QA engineer and TDD developer. Task: write unit tests for the code below: [PASTE CODE HERE] Output: - Happy-path tests: expected behavior - Edge cases: empty input, zero, min/max values, null/undefined - Error tests: expected errors and exceptions - Light integration tests for interactions with neighboring modules (if needed) - Declared coverage: which lines/branches are covered Rules: - Descriptive test names: should_do_x_when_y - Mock only external boundaries - Tests must be independent of execution order
